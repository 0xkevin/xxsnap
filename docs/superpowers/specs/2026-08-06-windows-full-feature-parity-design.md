# XxSnap Windows 完整功能与 macOS 视觉对齐设计

**状态：** 已完成对话设计确认，等待仓库规格最终审阅  
**日期：** 2026-08-06  
**目标分支：** `feature/windows-region-capture-mvp`

## 1. 背景

当前 Windows 实现是区域截图 MVP。它具备真实的多屏捕获、选区、复制、保存、托盘、单实例、Modern/Legacy 构建与四包安装能力，但工具条仅包含取消、保存和复制。macOS 现有的完整标注、贴图、滚动截图、全屏截图、OCR、教笔、设置等能力尚未移植。

本设计废止“区域截图 MVP 即 Windows 版本完成”的交付口径。Windows 后续交付以当前 macOS 产品为唯一功能、图标、尺寸、样式和交互基准；安装包仅在完整对齐验收通过后重新提供试用。

## 2. 目标

1. Windows 区域截图主工具条与 macOS 保持相同的按钮顺序、逻辑尺寸、图标显示尺寸、间距、分组、状态和拖动行为。
2. Windows 二级选项工具条、菜单、滑块、色板、提示信息和光标反馈与 macOS 保持一致。
3. 移植 macOS 当前全部真实功能，不显示无实现的占位按钮。
4. 复制、保存和贴图消费同一份标注合成结果，保证屏幕预览与输出一致。
5. 在 Windows 11/10 Modern x64、Windows 10 Modern x86、Windows 7 SP1 Legacy x64/x86 产品矩阵内维持既定兼容性。
6. 保留原始 macOS 图标，不重新设计、不替换、不改变比例。

## 3. 非目标

- 不采用 Windows 系统工具条、系统图标或系统控件重新诠释 macOS 设计。
- 不为了快速展示而加入不可操作的按钮或模拟成功行为。
- 不在本轮重写已通过验证的 DXGI/GDI 捕获、跨屏选区、PNG、剪贴板和安装矩阵。
- 不把 macOS 平台 API 直接带入 Windows；共享的是领域规则和资源契约，不是 AppKit 实现。

## 4. 尺寸和 DPI 契约

macOS 中的一个 point 映射为 Windows 中的一个 DIP。渲染时使用工具条所在显示器的当前 DPI：

```text
physicalPixels = logicalDip * monitorDpi / 96
```

布局始终在 DIP 中计算，只在渲染和输入边界转换为物理像素。跨越不同 DPI 显示器时，以实际承载工具条的显示器重新计算物理尺寸，不沿用截图会话启动时的比例。

必须验证以下缩放档位：

- 96 DPI / 100%
- 120 DPI / 125%
- 144 DPI / 150%
- 192 DPI / 200%

## 5. 主工具条视觉契约

### 5.1 几何

| 项目 | macOS 值 | Windows 值 |
|---|---:|---:|
| 工具条高度 | 28 pt | 28 DIP |
| 按钮区域 | 20 × 20 pt | 20 × 20 DIP |
| 按钮步距 | 28 pt | 28 DIP |
| 水平内边距 | 4 pt | 4 DIP |
| 左右拖动柄 | 20 × 20 pt | 20 × 20 DIP |
| 按钮垂直偏移 | 4 pt | 4 DIP |
| 分组额外间距 | 8 pt | 8 DIP |

工具条两端各保留一个拖动柄。额外分组间距只出现在橡皮擦、滚动截图和重做按钮之后。面板背景、边框、圆角、透明度、分隔线、悬停、选中和禁用状态按 macOS 当前绘制规则建立视觉金图，不使用 Windows 原生控件外观。

### 5.2 按钮顺序

普通区域截图的固定顺序为：

1. 矩形/椭圆
2. 箭头/折线
3. 画笔
4. 马克笔
5. 取色/测距
6. 马赛克
7. 文字
8. 序号
9. 放大镜
10. 橡皮擦
11. 滚动截图
12. 撤销
13. 重做
14. 取消
15. 贴图
16. 保存
17. 复制

最终实现不得为了适配屏幕宽度而压缩按钮或缩小图标。空间不足时沿用 macOS 的工具条放置、选区内回退和安全边界规则。

### 5.3 图标资源和显示尺寸

macOS `platforms/mac/Resources/Icons` 是唯一图标源。Windows 不允许使用近似图标。主工具条映射如下：

| 动作 | 原始资源名 | 20 DIP 按钮内缩 | 显示边界 |
|---|---|---:|---:|
| 拖动柄 | `settings-more` | 2 | 16 × 16 DIP |
| 矩形 | `screenshot` | -1 | 22 × 22 DIP |
| 箭头 | `arrow` | 0 | 20 × 20 DIP |
| 画笔 | `pencil-tool` | 2 | 16 × 16 DIP |
| 马克笔 | `highlighter-tool` | 2 | 16 × 16 DIP |
| 取色 | `straw-ranging` | 0 | 20 × 20 DIP |
| 马赛克 | `masaike2` | 0 | 20 × 20 DIP |
| 文字 | `text-tool` | 0 | 20 × 20 DIP |
| 序号 | `number-sequence` | 3 | 14 × 14 DIP |
| 放大镜 | `zoom-in-tool` | 2 | 16 × 16 DIP |
| 橡皮擦 | `eraser-tool` | 2 | 16 × 16 DIP |
| 滚动截图 | `scroll-screen2` | 0 | 20 × 20 DIP |
| 撤销/重做 | 对应 enabled/disabled 资源 | 0 | 20 × 20 DIP |
| 取消 | `cancel-capture` | 2 | 16 × 16 DIP |
| 贴图 | `pin-to-screen` | 2 | 16 × 16 DIP |
| 保存 | `save-to-file` | 2 | 16 × 16 DIP |
| 复制 | `copy-to-clipboard` | 2 | 16 × 16 DIP |

原始 SVG/PNG 文件建立 SHA-256 清单。Modern 与 Legacy 共用同一资源清单。Win7 无可靠系统 SVG 渲染能力，因此构建阶段从原始 SVG 机械生成 1x/1.25x/1.5x/2x 位图资源；原始文件仍是源文件，派生资源不得手工修改。视觉测试验证比例、透明区域、模板着色和固定颜色资源。

## 6. 二级工具条契约

每种工具的二级工具条必须同时移植布局、输入和真实行为：

- 矩形/椭圆：线宽、填充、形状、线型、圆角和颜色。
- 箭头/折线：线宽、线型、起点箭头、终点箭头和颜色。
- 画笔：线宽、线型和颜色。
- 马克笔：固定透明度、线宽和颜色。
- 马赛克：滑动/矩形模式、强度和笔触尺寸。
- 文字：粗体、斜体、描边、字体、字号和颜色。
- 序号：标记类型、尺寸和颜色。
- 放大镜：形状、缩放倍率、边框尺寸和颜色。
- 橡皮擦：点擦、框擦和全部清除。

普通二级工具条沿用 macOS 的 10 DIP 水平内边距。标准高度为一行色板 30 DIP、两行色板 40 DIP；马赛克和橡皮擦为 28 DIP。宽度、色块尺寸、控件间距、下拉菜单和圆角面板均直接来自 macOS `SelectionToolbarState` 的当前值。

## 7. 功能架构

### 7.1 视觉与状态层

- `ToolbarParityCatalog`：保存按钮顺序、资源、尺寸、内缩、分组和样式常量。
- `ToolbarLayout`：纯函数，根据模式、可见按钮、DPI 和安全边界生成主工具条、二级工具条、菜单及命中区域。
- `ToolbarState`：保存当前工具、当前样式、撤销/重做可用性、滚动截图状态和按钮可见/禁用状态。
- `ToolbarRenderer`：只消费布局和状态，不自行重新计算位置。
- `ToolbarInputRouter`：只消费同一份布局结果进行命中测试，避免绘制区域与点击区域漂移。

### 7.2 标注领域层

- `AnnotationDocument` 保存标注顺序、选中项和当前编辑状态。
- `CaptureAnnotation` 使用明确类型表示矩形、椭圆、箭头、折线、画笔、马克笔、马赛克、文字、序号和放大镜。
- `AnnotationStyle` 保存线宽、颜色、填充、透明度、字体、字号、箭头、马赛克强度等可序列化状态。
- `AnnotationCommand` 表示创建、移动、缩放、旋转、样式修改、擦除和清空，统一进入撤销/重做历史。
- 标注几何和命令历史位于可移植 C++17 层；Win32、D2D、DWrite 对象不进入领域模型。

### 7.3 Windows 表现层

- `OverlayController` 协调选区、工具条、标注编辑、滚动截图切换和终止动作。
- `AnnotationRenderer` 使用 Direct2D/DirectWrite 绘制实时标注。
- `AnnotatedSelectionComposer` 将冻结桌面、选区和标注文档合成为最终 BGRA 像素。
- 复制、保存和贴图必须使用同一个合成结果。
- 工具条资源加载失败时当前会话明确报告资源错误，不能用 Windows 系统图标静默替换。

## 8. 功能范围

完整 Windows 对齐包含：

1. 区域截图及跨显示器选择。
2. 全套标注工具和二级选项工具条。
3. 撤销、重做、删除、移动、缩放和旋转。
4. 复制、保存、贴图和结束编辑。
5. 滚动截图及预览、暂停、恢复、完成和取消。
6. 全屏截图及预览动作。
7. OCR、文本/二维码识别及结果展示。
8. 教学画笔及其独立工具条布局。
9. 设置、快捷键、托盘入口、帮助、诊断和商业权限行为。
10. macOS 当前存在且用户可见的状态、错误反馈和空状态。

快捷键统一把 macOS Command 映射为 Windows Ctrl：区域截图 `Ctrl+\``、全屏截图 `Ctrl+Shift+1`、OCR `Ctrl+3`、教笔 `Ctrl+2`。四个快捷键必须连接到真实功能后才算完成。

## 9. 数据流

```text
冻结桌面
  → 选区确定
  → 工具条选择工具和样式
  → 指针/键盘输入生成 AnnotationCommand
  → AnnotationDocument 更新并记录历史
  → AnnotationRenderer 实时预览
  → 复制/保存/贴图
  → AnnotatedSelectionComposer 输出最终像素
```

滚动截图、全屏截图和 OCR 作为独立会话接入应用协调器，不与区域标注会话共享可变平台对象；它们只共享像素、几何、导出和资源契约。

## 10. 错误和生命周期

- 工具切换时未完成的临时标注按 macOS 语义提交或取消，不留下半成品。
- D2D 设备丢失时重建设备资源，领域文档和撤销历史不丢失。
- 字体或文本布局失败时保留现有标注文档并显示明确错误。
- 贴图、保存、剪贴板或 OCR 失败不得提前清除截图会话。
- 滚动截图失败可重试或取消，不把不完整拼接图当作成功结果。
- 显示器拓扑变化沿用现有安全重启逻辑；重启前不导出旧拓扑像素。
- 应用退出、系统关机和会话取消必须释放覆盖窗口、鼠标捕获、热键和后台任务。

## 11. 实施分解

完整对齐拆成以下连续子项目，每个子项目单独形成实施计划和可验证提交：

1. 工具条视觉契约、完整布局、资源管线和状态模型。
2. 标注文档、撤销/重做及矩形/椭圆。
3. 箭头/折线、画笔和马克笔。
4. 取色/测距、马赛克和橡皮擦。
5. 文字、序号和放大镜。
6. 统一合成、复制、保存与贴图。
7. 滚动截图。
8. 全屏截图、OCR/二维码识别和教笔。
9. 设置、托盘、快捷键、帮助、诊断和商业功能对齐。
10. 全矩阵性能、视觉回归和安装包发布。

子项目可以产生开发者内部构建，但在主工具条出现的按钮必须具备真实行为。对用户提供的新试用包必须等全部子项目通过验收。

## 12. 测试策略

### 12.1 契约测试

- 从 macOS 当前实现锁定主工具条和二级工具条常量。
- 校验按钮顺序、资源名、图标内缩、额外间距和工具条宽度。
- 校验原始资源 SHA-256，禁止无意替换。
- 校验 96/120/144/192 DPI 下 DIP 到物理像素的舍入。

### 12.2 领域测试

- 每种标注的创建、编辑、命中、移动、缩放、旋转和删除。
- 每种样式选项及默认值。
- 撤销/重做覆盖创建和所有编辑命令。
- 马赛克、文字和放大镜覆盖边界、内存预算和失败路径。

### 12.3 渲染与导出测试

- 主工具条、各二级工具条、菜单、悬停、选中和禁用状态视觉金图。
- 标注预览与最终导出像素一致性。
- 原始图标在 100%/125%/150%/200% 下的透明度、比例和着色。
- 多显示器、负坐标、混合 DPI 和跨屏选区。

### 12.4 应用流程测试

- 区域截图、全屏截图、OCR、教笔四个快捷键端到端测试。
- 托盘所有入口连接真实功能。
- 贴图、滚动截图和错误恢复。
- Modern x64/x86 与 Legacy x64/x86 构建、测试和导入审计。

### 12.5 人工视觉验收

在 Parallels Windows 11 中分别使用 100%、150%、200% 缩放截取工具条，与同状态 macOS 参考图并排检查：

- 工具条外框和位置
- 图标边界和视觉重心
- 分组间距和分隔线
- 选中、禁用和悬停颜色
- 二级工具条对齐
- 文本基线和提示框

## 13. 完成定义

同时满足以下条件才可称为 Windows 完整版本：

1. 本设计列出的用户功能全部存在真实实现。
2. 主工具条与二级工具条通过尺寸、资源和视觉金图验证。
3. 四个应用快捷键连接真实功能。
4. 复制、保存和贴图结果与预览一致。
5. Modern 与 Legacy 四个目标通过各自完整测试矩阵。
6. 没有用户可见的占位按钮或“功能开发中”行为。
7. Parallels 人工视觉验收通过。
8. 最终 MSI 重新构建、解包验证并完成签名发布要求检查。
