# macOS 首选项与更新入口设计

## 目标

为 XxSnap 的菜单栏应用补齐原生首选项体验，并在状态栏菜单中新增“首选项…”和“检查更新…”入口。

首选项窗口提供五个分类：

1. 通用
2. 快捷键
3. 保存
4. 更新
5. 关于

本期交付真实可用的开机自启动、语言切换、快捷键配置和文件名模板功能。更新功能只完成菜单、设置、状态和后续服务接入位置，不进行网络请求、版本比较、后台定时检查、下载或安装。

## 当前状态

- `StatusItemController` 只有“截图”和“退出”两个菜单项，文字固定为中文。
- 应用采用 AppKit accessory 模式，没有首选项窗口。
- `AppSettings` 已保存语言、调色板、字体、快捷键字典和授权信息。
- `SettingsStore` 将整个 `AppSettings` JSON 保存到 `UserDefaults` 的 `appSettings.v1`。
- 当前自动合成的 `Codable` 解码要求所有字段存在。直接增加必填字段会导致旧设置整体回退到默认值。
- `CaptureHotKeyController` 固定注册两个 Carbon 全局快捷键：
  - 截图：`Command + \``
  - 恢复最近隐藏的贴图：`Command + 1`
- 普通截图和贴图保存都使用 `CaptureCoordinator.defaultCaptureFilename()`，当前默认值为 `xxsnap 截图 yyyyMMdd-HHmmss.png`。
- 工程没有 Sparkle、更新清单或其他更新服务。
- macOS 最低版本支持通过 `SMAppService.mainApp` 管理登录启动。
- 应用版本和构建号已由 `MARKETING_VERSION`、`CURRENT_PROJECT_VERSION` 写入 `Info.plist`。

## 已选方案

使用原生 AppKit 实现首选项窗口，沿用现有 `SettingsStore`、Carbon 全局快捷键和 AppDelegate 生命周期。

不引入 SwiftUI 设置场景或第三方更新框架。这样可以保持现有窗口、状态和测试方式一致，也避免为一个中等规模设置窗口维护第二套状态管理。

## 状态栏菜单

菜单按以下分组和顺序构建：

```text
截图                         当前配置的截图快捷键
────────────────────────────────────
首选项…                     Command + ,
检查更新…
关于 XxSnap
────────────────────────────────────
退出                         Command + Q
```

行为要求：

- “首选项…”打开首选项窗口。窗口已存在时只置前，不创建第二个实例。
- “检查更新…”执行本期占位检查，并显示“已是最新版本”。
- “关于 XxSnap”打开同一个首选项窗口并选中“关于”分类。
- “截图”右侧显示当前生效的截图快捷键。快捷键变更或恢复默认后，菜单同步刷新。
- 当前配置的截图快捷键注册失败时，菜单不显示快捷键等效键，避免展示一个无法全局触发的组合；点击菜单仍可截图。
- 菜单标题、状态栏提示和首选项文字随语言设置立即刷新。
- 语言切换不重建状态栏项目，不影响当前截图或贴图窗口。

英文菜单对应：

```text
Capture
Preferences…
Check for Updates…
About XxSnap
Quit
```

## 首选项窗口

窗口采用经典 macOS 顶部工具栏分类导航。工具栏从左到右为“通用、快捷键、保存、更新、关于”。

窗口要求：

- 使用单个 `NSWindowController` 管理。
- 窗口重复打开时复用并置前。
- 切换分类时保持窗口位置，内容区域不出现水平滚动。
- 设置即时生效，不设置单独的“应用”按钮。
- 文本字段仅在输入有效时提交；无效内容保留编辑焦点并展示就地错误。
- 中英文文字完整显示，不使用截断省略号隐藏设置名称或错误信息。

## 通用

### 开机自启动

显示一个开关：

- 默认状态取自 `SMAppService.mainApp.status`，而不是复制到 `AppSettings`。
- 开启时调用 `register()`。
- 关闭时调用 `unregister()`。
- 操作成功后重新读取系统状态。
- 操作失败时开关恢复为系统真实状态，并显示可理解的错误提示。
- 状态为 `.requiresApproval` 时不开启开关，显示“需要在系统设置中允许”，并提供打开“登录项”设置的按钮。
- 状态为 `.notFound` 时显示服务不可用错误，不把它当作普通关闭状态。
- 不轮询系统状态。打开首选项窗口或重新进入“通用”页时刷新一次。

默认情况下，未注册登录启动的应用显示关闭。

### 语言

使用 `English / 中文` 选项，默认沿用用户当前保存值；没有保存值时使用中文。

切换后：

- 立即保存 `AppSettings.language`。
- 立即刷新状态栏菜单、状态栏提示和首选项窗口。
- 下一次开始截图时创建一个语言快照。该快照贯穿区域截图、滚动截图提示、滚动截图控制器、完成后的长图编辑器和失败回退流程。
- 已经开始的完整截图工作流保持其语言快照，避免同一次截图流程混用两种语言或在操作中改变控件尺寸。
- 新语言只影响切换后开始的新截图工作流。

## 快捷键

本期开放两个真实存在的全局动作：

| 动作 | 默认快捷键 |
| --- | --- |
| 截图 | `Command + \`` |
| 恢复最近隐藏的贴图 | `Command + 1` |

快捷键页使用可扩展列表，每行包含动作名称、当前组合键和“录制”按钮。底部提供“恢复默认快捷键”。

录制规则：

- 点击“录制”后，该行进入等待输入状态。
- `Escape` 取消录制并保留原值。
- 新组合必须包含至少一个 `Command`、`Option`、`Control` 或 `Shift` 修饰键。
- 只按修饰键不构成有效组合。
- 两个 XxSnap 动作不能使用相同组合。
- 新组合先尝试注册，注册成功后再替换旧组合并保存。
- 系统注册失败时保留旧组合并显示错误，不留下未注册状态。
- 修改“恢复最近隐藏的贴图”快捷键时，继续遵守当前截图覆盖层的动态启停规则，不能吞掉覆盖层中的既有快捷键。
- 截图工作流进行中时禁用快捷键录制和恢复默认，显示“截图进行中”，避免验证恢复贴图快捷键时吞掉覆盖层事件。
- 恢复默认值是一个原子操作：两个默认组合都注册成功后才保存；任一注册失败时恢复两个旧注册和旧设置。
- 应用启动时按保存值注册快捷键。某个保存值注册失败时保留该配置但标记为不可用，不静默覆盖用户设置；快捷键页显示错误，相关菜单项不展示无效等效键。
- 设置中缺少某个动作时才使用该动作默认值。

数据结构按稳定动作标识保存，本期动作标识为：

```text
capture
restoreMostRecentlyHiddenPinnedImage
```

列表和存储允许以后增加保存、复制、贴图、工具切换等动作，但本期不开放这些截图过程快捷键。

## 保存

### 文件名模板

默认模板保持现有文件命名行为：

```text
xxsnap 截图 {yyyyMMdd}-{HHmmss}
```

支持两个明确变量：

- `{yyyyMMdd}`：本地日期，例如 `20260723`
- `{HHmmss}`：本地时间，例如 `160835`

界面在输入框下实时显示带 `.png` 扩展名的完整预览：

```text
xxsnap 截图 20260723-160835.png
```

验证规则：

- 模板去除首尾空白后不能为空。
- 模板不能包含路径分隔符或生成路径层级。
- 未识别变量显示错误，不静默保留花括号内容。
- 预览和实际保存共用同一个渲染器，避免显示值与保存值不一致。
- 扩展名由保存流程统一补充，模板本身不要求包含 `.png`。
- 设置无效时不覆盖上一次有效模板。

模板同时用于：

- 截图完成后的保存面板。
- 贴图窗口的保存面板。
- 长图编辑器保存。
- 长图编辑器不可用时的失败回退保存。

`CaptureCoordinator` 和 `PinnedImageWindowController` 不各自拼接文件名。两者通过工厂或初始化参数接收同一个文件名提供器；长图保存和失败回退继续经过 `CaptureCoordinator` 的共享保存入口。

用户仍可在 `NSSavePanel` 中修改最终文件名。

## 更新

设置项：

- “启动时检查更新”开关，默认开启。
- “自动检查间隔”选择器，默认 `24 小时`。
- 固定间隔：`1 / 6 / 12 / 24 / 48 / 72` 小时。
- “立即检查”按钮。
- 当前状态文字。

本期行为：

- 开关和间隔正常保存。
- 点击状态栏菜单“检查更新…”或设置页“立即检查”，状态显示“已是最新版本”。
- 不发送网络请求。
- 不启动后台计时器。
- 不进行版本比较、下载或安装。
- 不伪造“最后检查时间”。

“已是最新版本”是本期已确认的产品占位文案，不代表完成了网络验证。代码中的结果类型必须明确区分占位结果与未来真实的版本比较结果，不能写入“最后检查时间”或缓存为真实更新结论。

代码中保留可替换的更新检查服务接口，后续接入真实服务时，菜单和设置页调用同一个入口。占位服务只返回已确认的占位状态。

## 设置模型与兼容

现有 `AppSettings` 继续保存语言、既有界面设置、授权和 `hotkeys`，不向它的整体 JSON 增加本期专属字段。

新增独立的 `PreferencesSettings`：

```text
filenameTemplate: String
checksForUpdatesAtLaunch: Bool
updateCheckIntervalHours: Int
```

`PreferencesSettings` 保存到独立的 `preferencesSettings.v1` 键。现有 `hotkeys` 字典继续保存快捷键，缺少动作值时使用该动作默认值。

兼容要求：

- 保持 `appSettings.v1` 的现有字段与解码兼容，保留语言、调色板数量、字体、快捷键和授权数据。
- 为 `PreferencesSettings` 提供显式兼容解码，缺失字段使用各自默认值。
- 旧版本只会读写 `appSettings.v1`，不会删除独立 `preferencesSettings.v1` 中的新偏好，支持用户临时回退旧版本后再次升级。
- 未知的新字段可由旧版本忽略。
- 间隔字段解码后必须归一到允许集合；无效值回退到 `24`。
- 文件名模板缺失时回退到保持现有命名行为的默认模板。
- 单个新增偏好字段损坏不能导致其他新增偏好或现有 `AppSettings` 重置。

登录启动不写入 `AppSettings`，系统服务状态是唯一事实来源。

## 组件边界

### AppDelegate

`AppDelegate` 负责创建并共享：

- `SettingsStore`
- `PreferencesSettingsStore`
- `CaptureCoordinator`
- `CaptureHotKeyController`
- `StatusItemController`
- `PreferencesWindowController`
- 登录启动服务
- 占位更新检查服务

它负责连接设置变化，但不包含具体视图布局或文件名解析逻辑。

### PreferencesWindowController

负责：

- 单窗口生命周期。
- 五分类工具栏与内容切换。
- 将控件事件交给对应设置或平台服务。
- 在语言变化后刷新可见文本，同时保留当前分类和窗口位置。
- 打开时指定初始分类，支持菜单中的“关于 XxSnap”直达关于页。

### CaptureHotKeyController

从当前私有固定注册逻辑扩展为可重新配置的控制器：

- 按动作注册、注销和替换快捷键。
- 保留截图期间动态禁用恢复贴图快捷键的现有行为。
- 对外返回明确注册结果，便于首选项显示冲突。
- 暴露每个动作的配置值和实际注册状态，供菜单和首选项使用同一个有效状态。
- 批量恢复默认时支持事务式回滚，不留下只恢复一个动作的部分状态。
- 不新增键盘监听权限、轮询或事件窃听。

### CaptureFilenameProviding

纯逻辑组件，负责：

- 验证模板。
- 用指定日期和时区生成文件名。
- 统一预览与实际保存结果。

该组件不依赖 AppKit，便于确定性测试。`CaptureCoordinator` 和贴图窗口工厂接收同一个提供器，普通截图、长图编辑、长图失败回退和贴图保存均通过它生成 `NSSavePanel` 建议名称。

### LaunchAtLoginManaging

协议封装 `SMAppService.mainApp` 的状态、注册和注销。生产实现调用系统服务，测试使用可控假实现。

### UpdateChecking

菜单和设置页依赖同一协议。本期实现返回类型明确的占位结果，并映射为“已是最新版本”，不包含网络能力。

### Settings persistence

设置持久化通过可注入协议隔离。生产实现编码后写入 `UserDefaults`，测试实现可模拟编码或保存失败。视图控制器只有在持久化成功后才确认新的内存状态；失败时恢复上一次有效值并提示，不假设 `UserDefaults.set` 自身提供错误返回。

## 错误处理

- 登录启动注册失败：恢复系统真实开关状态并显示错误。
- 登录启动需要批准：显示系统设置入口，调用 `SMAppService.openSystemSettingsLoginItems()`，用户返回首选项后重新读取状态。
- 登录启动服务不存在：显示不可用状态，不反复尝试注册。
- 快捷键格式无效：保持录制状态或允许取消，不修改现有注册。
- 快捷键重复或系统注册失败：保留旧快捷键并显示错误原因。
- 启动时保存的快捷键无法注册：保留配置并标记不可用，不静默改写；截图菜单仍可点击。
- 文件名模板无效：显示输入错误，保留上一次有效设置。
- 设置编码或持久化服务报告失败：恢复上一次有效状态并提示保存失败。
- 应用图标缺失：关于页回退到 `NSImage(named: NSImage.applicationIconName)`，不使用状态栏黑白模板图。
- 版本字段缺失：显示可理解的占位值，不导致窗口创建失败。

## 性能与回归约束

- 首选项窗口按需创建并复用，不在每次菜单点击时重建。
- 不增加常驻轮询、更新计时器或网络请求。
- 快捷键只在启动、设置变更和截图会话边界重新注册。
- 文件名预览仅在模板变化时计算。
- 不改变截图、滚动截图、长图编辑、贴图、剪贴板和保存面板的既有流程。
- 默认快捷键和默认文件名保持当前行为。
- 设置迁移不能重置用户已有配置。

## 测试

### 设置与迁移

1. 现有 `appSettings.v1` 加载后，语言、调色板、字体、快捷键和授权保持不变。
2. 独立 `PreferencesSettings` 缺失时使用确认的默认值。
3. 旧版本重写 `appSettings.v1` 后，独立的新偏好仍能再次加载。
4. 无效更新间隔回退到 `24`，单个损坏字段不重置其他偏好。
5. 两个设置存储保存并重新加载后保持一致。
6. 注入的保存失败会恢复上一次有效界面状态。

### 文件名模板

1. 默认模板生成与现有格式相同的名称。
2. 日期、时间和时区渲染确定。
3. 空模板、路径分隔符和未知变量被拒绝。
4. 预览与普通截图、贴图保存、长图编辑保存及长图失败回退使用同一结果。
5. 贴图窗口通过注入的提供器获取名称，不保留独立命名逻辑。

### 快捷键

1. 默认动作解析为 `Command + \`` 和 `Command + 1`。
2. 有效组合注册成功后替换旧组合并持久化。
3. 重复组合、无修饰键组合和系统注册失败均保留旧组合。
4. `Escape` 取消录制。
5. 截图进行中禁用快捷键录制和恢复默认。
6. 恢复默认快捷键可原子回到两个确认值，任一失败时两个动作都回滚。
7. 启动时保存组合注册失败会标记不可用，不覆盖设置。
8. 截图覆盖层出现时，恢复贴图快捷键仍按现有行为注销；会话结束后按最新设置恢复。
9. 截图快捷键变更后菜单同步展示实际生效组合，注册失败时不展示无效组合。
10. 快捷键注册成功但持久化失败时，注册、配置和菜单显示一起回滚。
11. 两个动作当前组合互换后执行“恢复默认”，仍可完成事务式恢复，不受旧注册占用影响。

### 菜单与窗口

1. 菜单项顺序、分隔线和快捷键正确。
2. “首选项…”重复点击复用同一窗口。
3. “关于 XxSnap”直达关于页。
4. 语言切换立即刷新菜单和首选项。
5. 从截图开始到滚动截图、长图编辑或失败回退结束共用一个语言快照，新工作流使用新语言。
6. 异步桌面捕获进行中切换语言时，当前工作流继续使用开始时快照，下一工作流使用新语言。

### 平台服务

1. 登录启动成功时开关反映系统状态。
2. 注册或注销失败时开关回滚并显示错误。
3. `.requiresApproval` 状态显示批准提示和系统设置入口，重新进入页面后可刷新为真实状态。
4. `.notFound` 状态显示不可用错误。
5. 占位更新检查不访问网络并返回“已是最新版本”。
6. 更新偏好可保存，但不创建后台计时器。

## 验收标准

- 状态栏菜单新增入口，顺序、快捷键和中英文显示符合设计。
- 首选项窗口采用原生 AppKit 顶部工具栏，并完整提供五个分类。
- 开机自启动真实调用系统服务，并能正确处理失败。
- 登录启动需要系统批准时提供明确状态和系统设置入口。
- 语言切换立即刷新菜单和首选项，后续截图会话使用新语言。
- 两个全局快捷键可录制、校验、应用、持久化和恢复默认。
- 默认快捷键及截图期间的动态路由行为不倒退。
- 状态栏菜单展示的截图快捷键与实际注册状态一致。
- 文件名模板实时预览，并用于所有既有保存入口。
- 默认文件名格式不倒退。
- 更新设置可保存，检查入口按本期要求显示“已是最新版本”，且没有网络、计时器、下载或安装行为。
- 关于页使用彩色应用图标和动态版本信息。
- 升级后旧设置不会因新增字段而整体重置。
- 临时运行旧版本不会删除独立保存的新偏好。
