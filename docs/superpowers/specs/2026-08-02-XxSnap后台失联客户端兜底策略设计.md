# XxSnap 后台失联客户端兜底策略设计

## 背景

XxSnap 当前处于全功能免费阶段。滚动截图、OCR 和教笔虽然已经接入未来的 Pro 权限控制，但现阶段所有用户都应直接使用这些功能，不应因为收费后台、域名、TLS、签名配置或网络出现故障而被锁住。

现有客户端在首次启动时会读取安装包内的已签名免费策略，但这份策略没有服务器时间锚点。如果此时又无法连接后台，权限状态会变成 `free`，三个未来 Pro 功能随即被拦截。实际诊断日志已经出现后台刷新网络失败和滚动截图被 `free` 状态拦截的问题。

本设计把“当前是否处于免费推广阶段”从远程策略中分离出来，改为由客户端版本在构建时确定。这样后台故障只影响策略刷新，不影响当前免费版的正常功能。

## 已确认的产品规则

1. 当前免费版后台失联时，无论是否有历史缓存，都永久开放全部功能。
2. 当前免费版即使收到后台 `paid` 策略，也不能开始收费，仍然开放全部功能。
3. 正式收费必须发布一个新的收费版客户端，不能只操作后台开关。
4. 联网的旧免费版在正式收费时必须升级；始终不联网的旧免费版会继续免费使用，这是永久开放兜底的必然结果。
5. 收费版中，已购买并成功激活的用户永久保留授权覆盖版本的 Pro 权限。
6. 收费版中，试用用户和未购买用户最多离线宽限 14 天。
7. 收费版首次安装且从未成功联网时，只提供 Free，不能离线开始试用。

## 方案选择

### 方案一：客户端版本锁定阶段

在客户端构建中写入不可由后台修改的发布阶段。免费版无条件开放全部功能；收费版才执行远程策略、试用和授权状态机。

优点：

- 当前免费体验不依赖后台可用性。
- 后台误发布收费规则也不会造成意外收费。
- 免费版和收费版的行为边界清楚，容易测试和审计。

代价：

- 正式收费必须发布新版客户端。
- 永久离线的旧免费版无法被远程切换为收费版。

### 方案二：完全由后台决定

客户端每次根据后台返回的策略决定免费或收费。

该方案在后台正常时灵活，但客户端断网时无法知道后台是否已经切换收费，会产生联网用户收费、离线用户免费的不一致，不采用。

### 方案三：内置限时免费策略

安装包内的免费策略设置有效期，过期后再提供 14 天宽限。

该方案能限制旧版本长期免费，但后台长期故障或首次离线启动会锁住功能，与已经确认的免费阶段永久兜底规则冲突，不采用。

## 总体架构

客户端增加构建字段：

```text
XXCommercialReleasePhase = free | paid
```

该字段属于客户端发布物，不从后台读取，也不能被远程策略覆盖。

### 构建规则

- 当前公开版本固定为 `free`。
- 正式收费新版改为 `paid`。
- Release 构建缺少该字段或值不是 `free`、`paid` 时直接失败，不能生成安装包。
- Debug 默认使用 `free`，保证本地开发不会因测试后台或测试公钥故障而锁住截图功能。
- Release 打包必须验证发布阶段、生产公钥和内置启动策略三者一致。

### 组件职责

`CommercialReleasePhase` 只负责解析并暴露不可变的客户端发布阶段。

`CommercialAccessController` 继续负责远程策略、缓存、试用、授权和权限快照，但必须先判断发布阶段：

- `free` 阶段直接发布 `allFree` 权限快照。
- `paid` 阶段才根据已验签策略、授权凭证和离线时间计算权限。

`CommercialPolicyClient` 继续负责后台请求和响应解析。免费阶段仍可刷新后台，用于发现服务异常，但请求结果不能降低功能权限。

`CommercialSignatureVerifier` 继续负责 Ed25519 验签。公钥 ID 相同不代表可信，必须使用对应公钥实际验证签名。

`CommercialRefreshScheduler` 继续负责后台刷新和重试，但免费阶段的失败只能产生诊断信息，不能改变权限状态。

## 当前免费版状态机

客户端启动后先读取 `XXCommercialReleasePhase`。当值为 `free` 时：

1. 立即把权限状态设为 `allFree`。
2. 立即允许滚动截图、OCR 和教笔，不等待缓存、网络或服务器时间。
3. 不显示 `PRO`、购买入口或试用倒计时。
4. 后台异步刷新策略。

后台刷新结果按以下规则处理：

| 刷新结果 | 客户端行为 |
|---|---|
| 有效 `all_free` | 可以缓存，权限保持 `allFree` |
| 有效 `paid` | 拒绝执行，不写成有效权限缓存，权限保持 `allFree` |
| 签名错误或公钥不匹配 | 忽略响应，权限保持 `allFree` |
| 策略过期或时间异常 | 记录诊断，权限保持 `allFree` |
| DNS、TLS、超时、断网、服务器错误 | 后台重试，权限保持 `allFree` |
| 本地缓存损坏或不存在 | 忽略缓存，权限保持 `allFree` |

免费版不删除现有策略缓存、授权凭证或拒绝标记，只是在权限判断时以 `free` 发布阶段为最高优先级。收到 `paid` 策略时不能覆盖最后一份有效的 `all_free` 缓存。

## 未来收费版状态机

当 `XXCommercialReleasePhase=paid` 时，客户端执行收费状态机。

### 已购买用户

- 成功激活并验签后，将授权凭证安全保存在钥匙串中。
- 后台失联时，永久保留授权覆盖版本的 Pro 权限。
- 永久授权不等于永久更新；客户端构建号必须在授权允许的版本范围内。
- 如果客户端已经收到退款、撤销或设备停用结果，必须持久保存拒绝标记。重启或断网不能重新获得 Pro。
- 如果撤销发生后客户端始终没有联网，客户端无法提前知道撤销结果，这是离线永久授权必须接受的限制。

### 试用用户

- 试用必须联网开始，不能仅靠本机时间创建。
- 正常试用按后台签发的结束时间计算。
- 后台失联时最多额外宽限 14 天。
- 系统时间回拨、重启或重装不能延长试用或宽限期。
- 宽限结束后只保留 Free。

### 未购买用户

- 曾成功收到有效策略时，旧状态最多离线保留 14 天。
- 14 天后只保留 Free。
- 首次安装且从未成功联网时直接提供 Free，不开放 Pro，也不离线开始试用。

## 后台不可用时的处理

客户端要区分“刷新失败”和“权限失效”。两者不能再混为同一个状态。

免费版遇到以下错误时全部失败开放：

- DNS 解析失败；
- TCP 或 TLS 连接失败；
- 请求超时；
- HTTP `5xx`；
- 非法 JSON；
- 签名错误；
- 未知公钥；
- 策略尚未生效或已经过期；
- 服务器时间头缺失；
- 本地缓存或钥匙串读取失败。

失败开放只适用于 `free` 发布阶段。收费版仍按照已购买、试用、未购买三类规则处理，不能因为服务器错误让所有未购买用户永久获得 Pro。

后台刷新采用递增重试间隔：

```text
15 分钟 → 1 小时 → 6 小时
```

网络恢复、应用重新激活或用户主动检查时可以提前触发刷新。连续失败不能频繁请求，也不能反复向用户弹窗。

## 用户界面和诊断

免费版：

- 隐藏授权与购买页面；
- 不显示 `PRO` 标记；
- 不显示试用倒计时；
- 功能点击后直接执行，不出现购买拦截。

后台失败时默认不弹窗。诊断信息可以显示“后台策略暂时无法刷新，当前免费权限不受影响”。

诊断日志只记录：

- 发布阶段；
- 策略模式；
- 策略 ID；
- 请求结果；
- 稳定错误码；
- 当前权限类别。

不能记录私钥、公钥完整配置、授权码、邮箱、设备原始标识、Cookie 或完整后台响应。

当免费版收到 `paid` 时，记录稳定错误码 `paid_policy_ignored_in_free_release`，用于发现后台误操作，但不提示普通用户。

## 正式收费切换流程

1. 先完成真正可用的客户端更新和强制升级能力。当前更新检查仍是占位实现，在此能力完成前禁止正式收费。
2. 后台保持 `all_free`，构建并完整测试 `XXCommercialReleasePhase=paid` 的候选版本。
3. 候选版本必须使用生产公钥和生产私钥签名的内置启动策略，不能使用 Debug 测试密钥。
4. 发布收费版客户端。
5. 后台设置最低安全版本，联网的旧免费版提示并完成升级。
6. 确认新版覆盖率和支付、激活、退款、撤销链路正常后，管理员才能在后台发布 `paid`。
7. 严重故障时，后台“紧急恢复全部免费”仍可让收费版客户端恢复全部功能。

当前免费版永远拒绝执行 `paid`，所以只发布后台策略不能开始收费。始终不联网的旧免费版会继续免费使用，这是本方案明确接受的产品结果。

## 数据兼容和迁移

- 免费版升级后不清空钥匙串和缓存，避免破坏将来的授权迁移。
- 免费版忽略已有终止标记对功能权限的影响，但不删除标记。
- 收费版只接受生产公钥验签通过的数据。
- Debug 测试公钥签发的缓存、无法验签的数据和错误阶段的数据不能进入收费版权限判断。
- 从免费版升级到收费版时，旧的无时间锚点免费缓存不能直接授予 Pro。
- 已购买凭证只有在设备绑定、签名、版本范围和终止标记全部通过时才授予 Pro。

## 测试方案

### 免费版单元测试

- 首次启动、无缓存、完全断网时状态为 `allFree`。
- TLS 被重置、DNS 失败、超时和 HTTP `5xx` 时三个功能全部可用。
- 缓存缺失、损坏、过期或没有可信时间锚点时三个功能全部可用。
- 系统时间回拨时三个功能全部可用，但记录时间异常。
- 收到有效 `all_free` 时刷新成功，权限保持 `allFree`。
- 收到有效 `paid` 时拒绝执行，权限保持 `allFree`。
- 收到无效签名、未知公钥或同 ID 不同公钥的策略时权限保持 `allFree`。
- 收到 `paid` 后不覆盖最后一份有效 `all_free` 缓存。
- 不显示 `PRO`、购买页和试用倒计时。

### 收费版单元测试

- 首次离线安装只提供 Free。
- 已购买用户长期离线时保留授权覆盖版本的 Pro。
- 超出授权版本范围时不授予 Pro。
- 试用和未购买用户在 14 天边界前后行为正确。
- 时间回拨、重启和重装不能延长试用或宽限。
- 已退款、撤销或设备停用后，重启和断网不能恢复 Pro。
- 生产公钥、内置策略和后台签名不一致时构建或运行验证失败。

### 功能回归测试

以下入口必须分别测试，不能只验证权限状态枚举：

- 滚动截图工具栏按钮和快捷入口；
- OCR 菜单和快捷键；
- 教笔菜单和快捷键。

免费版每个入口都应直接执行。收费版无权限时才显示购买说明。

### 集成验收

1. 模拟 `download.xxsofts.com` 无法连接或 TLS 握手被重置。
2. 清空测试设备的策略缓存，模拟首次启动。
3. 启动当前免费版。
4. 诊断日志允许出现网络错误，但权限必须是 `allFree`。
5. 滚动截图、OCR 和教笔全部可以直接使用。
6. 不显示 `PRO`、购买页或试用倒计时。
7. 恢复后台连接并发布 `all_free`，确认刷新成功且权限不变。
8. 在隔离测试后台发布 `paid`，确认当前免费版拒绝执行且仍然全部免费。

## 验收标准

- 当前免费版的三个未来 Pro 功能不再依赖后台在线。
- 后台故障不能导致滚动截图按钮无反应。
- 后台误发 `paid` 不能让当前免费版开始收费。
- 免费版的网络、签名、缓存和时间错误都有脱敏诊断记录。
- 收费版仍能限制未购买用户，且保留已购买用户的永久版本授权。
- 14 天离线宽限只作用于收费版的试用和未购买状态。
- Release 构建能阻止缺少发布阶段、生产公钥或有效内置策略的安装包产生。
- 正式收费前必须先交付真实更新和强制升级能力。

## 本次范围

本设计只定义客户端后台失联兜底策略及收费切换边界。以下内容不在本次实现范围内：

- 支付接口；
- 邮件发送；
- 官网购买页；
- 客户端自动更新和强制升级的具体实现；
- 改变后台现有价格、试用天数或设备数量。

客户端自动更新和强制升级虽然不在本次实现范围内，但它是正式收费的硬性前置条件。该能力未完成前，后台必须保持 `all_free`。
