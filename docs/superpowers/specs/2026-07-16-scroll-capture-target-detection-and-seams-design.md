# 滚动截图区域识别、动态步长与接缝线设计

## 背景

当前滚动截图已经能够自动滚动和拼接，但聊天窗口通常同时包含会滚动的消息区与固定的侧栏、标题栏、输入框。若直接使用用户框选的整个窗口，固定区域会进入每一帧，既降低重叠匹配的稳定性，也容易产生重复或错误接缝。

网页长截图的有效滚动区域通常较高，固定使用 `30%` 的单步距离会造成点击次数过多；聊天消息区通常较小，固定使用 `50%` 又会减少相邻帧重叠。现有固定比例不能同时覆盖两类场景。

拼接预览和最终导出还需要明确标示每个真实拼接边界，但不能改变现有左侧预览布局或其中的蓝色视口定位框。

## 已确认的产品决策

- 自动识别仅在用户点击“滚动截图”工具后执行；普通截图、选区、标注及其他工具行为不变。
- 识别到纵向可滚动容器后，选区自动收紧到该容器与原选区的交集，四边改为绿色。
- 识别失败、无辅助功能权限或没有合格滚动容器时，不调整选区，四边保持蓝色；这不阻断原有滚动截图回退流程。
- 动态步长以识别后的实际滚动区域高度为准：高度达到 `600pt` 时单步滚动 `50%`，低于 `600pt` 时单步滚动 `30%`。
- 左侧拼接预览的位置、尺寸及蓝色视口定位框全部保持不变。
- 每个真实拼接边界显示约 `0.1pt` 的白色发丝线；拼接预览和最终导出都显示。

## 用户流程

1. 用户像现在一样完成普通蓝色选区。
2. 用户点击“滚动截图”。
3. macOS 外壳针对原选区和目标应用执行一次 Accessibility 语义识别。
4. 若找到合格的纵向滚动容器：
   - 将容器屏幕区域与原选区相交并像素对齐；
   - 选区收紧到相交结果；
   - 四边切换为绿色；
   - 使用收紧后的区域生成首帧、预览布局和后续采样区域。
5. 若没有找到合格容器：保留原选区和蓝色四边，继续使用现有滚动截图流程。
6. 自动滚动时根据最终选区高度选择 `30%` 或 `50%` 单步距离。
7. 每次可靠接受新片段后，在该真实片段边界记录一个接缝位置；左侧预览和最终导出在对应位置绘制白色发丝线。
8. 取消滚动截图时恢复进入滚动模式前的原选区与普通蓝色状态。

## 滚动区域识别

### 所属层级

识别依赖 macOS Accessibility，因此放在 `platforms/mac/`，不进入共享 C++ 核心。新增独立的 `ScrollCaptureTargetDetecting` 协议和默认 `AccessibilityScrollCaptureTargetDetector`，使生产代码与伪造 AX 层级的单元测试解耦。

`CaptureCoordinator` 负责确定目标应用 PID、发起检测并协调状态转换。`SelectionOverlayWindow` 只负责应用解析后的选区、边框语义和生成最终 `ScrollCaptureSeed`。

### 候选发现

检测器在原选区内生成中心点及规则网格探针，对每个探针调用 `AXUIElementCopyElementAtPosition`，再沿父节点向上搜索，最多 16 层。满足以下任一条件的元素进入候选集：

- 角色为 `AXScrollArea`，且具有可用的纵向滚动条；
- 能通过 `kAXVerticalScrollBarAttribute` 取得纵向滚动条，且滚动条 `maximum > minimum`。

检测器读取候选元素的 `AXPosition` 和 `AXSize`，完成 Quartz 顶部原点与 AppKit 底部原点之间的坐标转换，并将结果裁剪到原选区。无法读取几何信息、尺寸过小、与原选区没有有效交集或没有纵向可滚动范围的候选会被丢弃。

### 候选选择

聊天窗口可能同时暴露会滚动的会话侧栏和消息区。候选先按 AX 元素去重，再按以下顺序选择：

1. 与原选区相交面积更大；
2. 高度更大；
3. 中心更接近原选区中心。

这样整个聊天窗口被框选时通常会选择面积更大的消息滚动区，而不是狭窄侧栏。检测结果必须保留在原选区内部，绝不扩张用户最初授权的截图范围。

### 状态与视觉反馈

选区新增滚动目标视觉状态：

- `inactive`：普通工具状态，蓝色边框；
- `resolving`：点击滚动截图后正在识别，仍显示蓝色；
- `resolved`：识别成功并应用收紧区域，显示绿色；
- `fallback`：识别失败，保留原区域和蓝色；
- `capturing`：沿用 `resolved` 或 `fallback` 的边框颜色。

绿色仅表示“已通过 Accessibility 找到纵向可滚动容器”，不承诺动态内容、虚拟列表或动画一定能够无误拼接。绿色四边和选区控制点使用同一语义色，避免边框绿色、控制点蓝色造成混淆。进入捕获后选区不可编辑。

普通工具永远不触发检测，也不会因曾经进入滚动模式而保留绿色。取消后恢复进入滚动模式前保存的原选区。

### 注释与坐标

收紧操作发生在创建 `ScrollCaptureSeed` 之前。首帧截图、后续采样、预览布局、自动滚动探针点和步长均使用收紧后的屏幕区域。

已有注释和擦除蒙版保持其屏幕位置；生成种子时转换为新选区局部坐标。完全落在新选区外的内容不进入长图，跨越新边界的内容按新选区裁剪。这与用户选择自动收紧到滚动内容区的行为一致。

## 动态自动滚动步长

将当前固定的 `stepViewportRatio = 0.3` 替换为无副作用的策略函数：

```text
ratio(height):
  height >= 600pt -> 0.50
  height <  600pt -> 0.30
```

单步距离继续使用 `max(1pt, height × ratio)`，其中 `height` 是最终捕获区域的逻辑点高度，而非整块屏幕高度。边界探测、多个探针位置、鼠标恢复、键盘回退和滚动脉冲机制保持现状。

选择 `600pt` 是为了让常见浏览器正文区走 `50%`，同时让高度较小的聊天消息区保持 `70%` 重叠。阈值和比例先作为命名常量，后续若实测语料需要调整，可只修改策略而不改变会话流程。

## 白色拼接接缝线

### 语义

接缝只标记“一个已接受片段与前一个已接受片段的真实边界”。以下情况不生成接缝：

- 首帧顶部；
- 重复帧或回看帧；
- 低置信度丢弃帧；
- 正在等待固定区域证据但尚未接受新内容的帧。

向下捕获时接缝位于新追加片段的第一行；向上捕获时按最终自然文档顺序位于相邻已接受片段之间。接缝覆盖已有边界像素，不增加输出高度，也不插入空白内容。

### `0.1pt` 的像素实现

PNG 和当前 BGRA 合成结果不能保存小于一个物理像素的几何宽度。实现使用一行物理像素对白色做覆盖率混合，以模拟 `0.1pt` 发丝线：

```text
coverage = clamp(0.1 × backingScale, 0, 1)
outputRGB = sourceRGB × (1 - coverage) + white × coverage
```

例如 2× Retina 输入的覆盖率为约 `0.2`。这比一整行纯白像素更细、更淡，同时保持不透明 PNG 和剪贴板输出的一致性。

### 预览与最终输出一致性

共享拼接会话保留已接受片段的边界元数据。最终流式合成在写出对应源行时应用白色覆盖率。预览缩放不能依赖恰好采样到该源行，而是把每个源接缝映射到预览坐标，再在映射后的单行应用同一覆盖率规则。

接缝属于长图像素内容，因此长图编辑器、复制、保存和固定图片都会得到相同结果。现有左侧预览布局和蓝色视口定位框不参与该改动。

## 错误与回退

- AX 查询失败、权限不足、目标进程消失或几何数据无效：记录诊断日志，使用原蓝色选区继续。
- 多个候选得分完全相同：使用稳定的探针顺序作为最终决胜，避免选区来回跳动。
- 识别结果小于最小可捕获尺寸：视为识别失败，不应用收紧。
- 识别成功后首帧捕获失败：沿用现有启动失败恢复路径，并恢复原选区。
- 接缝元数据异常或映射越界：跳过该接缝，不能导致最终图像合成失败。

## 测试策略

### macOS 单元测试

- AX 层级包含主消息区和侧栏时选择面积更大的主消息区。
- 候选区域被严格裁剪在原选区内。
- 无权限、无滚动条、无范围或无几何信息时返回回退结果。
- 点击普通工具不会调用检测器；点击滚动截图只调用一次。
- 成功解析后选区收紧且边框为绿色；失败时选区和蓝色保持不变；取消恢复原选区。
- 已有注释和蒙版相对新选区正确平移、裁剪。
- `599pt` 使用 `30%`，`600pt` 及更高使用 `50%`。

### 共享核心与桥接测试

- 两个及多个已接受片段只在真实边界产生接缝。
- 重复、回看、低置信度和等待证据不新增接缝。
- 向上和向下拼接的接缝顺序正确。
- 最终合成使用按 backing scale 计算的白色覆盖率，不改变尺寸。
- 降采样预览仍能在映射位置显示接缝，且不会修改蓝色视口定位框。

### 手工验证

- 微信或同类聊天窗口：框选整个窗口，点击滚动截图后绿色选区收紧到消息区，侧栏、标题栏和输入框被排除。
- Safari/Chrome 长网页：较高区域使用 `50%` 步长，点击次数明显减少。
- 较小聊天区：使用 `30%` 步长，连续拼接保留足够重叠。
- Retina 与非 Retina：在左侧预览和最终 PNG 的 100% 缩放下检查白色接缝细度。
- 普通截图和其他工具：选区仍为蓝色，布局和行为无回归。

## 非目标

- 不改变左侧预览面板的位置、大小或交互。
- 不改变蓝色视口定位框。
- 不为普通截图或标注工具自动重选区域。
- 不增加应用专用的微信、浏览器或聊天软件规则。
- 不通过试滚或画面差分来识别滚动区域。
- 不移除现有低置信度匹配机制；本次通过缩小到真实滚动区来减少固定区域对匹配的干扰。
