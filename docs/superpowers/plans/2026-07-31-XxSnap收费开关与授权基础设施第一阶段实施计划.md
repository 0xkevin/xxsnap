# XxSnap 收费开关与授权基础设施第一阶段实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在所有功能继续免费的前提下，完成可由后台控制、不能被旧缓存永久卡住、支持十四天试用和手工激活码的收费基础闭环。

**Architecture:** `xxsnap-admin` 是收费规则、试用和授权的唯一可信来源，使用 Ed25519 给公开规则、试用凭证和授权凭证签名；macOS 客户端使用 CryptoKit 验签，把凭证保存在钥匙串中，并通过一个统一的权限控制器管理滚动截图、OCR 和教笔。生产配置默认并锁定为“全部免费”，只有后台确认支付链路已经就绪后，管理员才能二次确认切换到“开始收费”。

**Tech Stack:** Python 3.12、FastAPI、SQLAlchemy、Alembic、PostgreSQL、cryptography、React、TypeScript、Swift 5、AppKit、CryptoKit、Security、XCTest、pytest、Vitest。

## 固定接口契约

公开接口统一挂在 `https://download.xxsofts.com/api/v1/commercial`：

```text
GET  /policy
POST /trials/start
POST /licenses/activate
POST /licenses/validate
POST /licenses/deactivate
```

签名信封统一使用：

```json
{
  "keyId": "commercial-ed25519-2026-01",
  "payload": "base64-encoded-json-bytes",
  "signature": "base64-encoded-ed25519-signature"
}
```

签名对象的 JSON 使用 UTF-8、无缩进、键名排序和紧凑分隔符生成；客户端不重新序列化，直接对 `payload` 解码后的原始字节验签。

收费规则的核心字段固定为：

```json
{
  "schemaVersion": 1,
  "policyId": "uuid",
  "mode": "all_free",
  "billingReady": false,
  "effectiveAt": "2026-07-31T00:00:00Z",
  "expiresAt": "2026-08-30T00:00:00Z",
  "trialDays": 14,
  "updateMonths": 12,
  "deviceLimit": 3,
  "minimumSafeVersion": "1.0.0",
  "features": {
    "scroll_capture": false,
    "ocr": false,
    "teaching_pen": false
  },
  "purchase": {
    "regularPriceCny": 68,
    "launchPriceCny": 48,
    "renewalPriceCny": 34,
    "zhCNURL": "https://xxsnap.xxsofts.com/zh-CN/pro",
    "enURL": "https://xxsnap.xxsofts.com/en/pro"
  },
  "copy": {
    "zhCN": {
      "proRequired": "此功能需要 XxSnap Pro",
      "trialUnavailable": "暂时无法开始试用，请稍后重试"
    },
    "en": {
      "proRequired": "This feature requires XxSnap Pro",
      "trialUnavailable": "The trial cannot be started right now. Please try again."
    }
  }
}
```

`mode=all_free` 时 `features` 的值不参与限制，所有功能都开启，也不显示 `PRO`。`mode=paid` 只有在规则的 `billingReady=true` 且服务端部署配置
`commercial_billing_capability_enabled=true` 时允许发布；三个 `features` 字段决定对应功能是否属于 Pro。

- [ ] **Step 4: 实现签名信封**

```python
class SignedEnvelope(BaseModel):
    key_id: str = Field(alias="keyId")
    payload: str
    signature: str


def canonical_payload(value: BaseModel | dict[str, object]) -> bytes:
    data = value.model_dump(mode="json", by_alias=True) if isinstance(value, BaseModel) else value
    return json.dumps(
        data,
        ensure_ascii=False,
        sort_keys=True,
        separators=(",", ":"),
    ).encode("utf-8")


class CommercialSigner:
    def sign(self, value: BaseModel | dict[str, object]) -> SignedEnvelope:
        payload = canonical_payload(value)
        return SignedEnvelope(
            keyId=self.key_id,
            payload=base64.b64encode(payload).decode("ascii"),
            signature=base64.b64encode(self.private_key.sign(payload)).decode("ascii"),
        )
```

私钥只从环境变量读取，不写数据库、不写日志、不进入 Git。测试使用运行时生成的临时密钥。

struct CommercialSignatureVerifier {
    let publicKeys: [String: Curve25519.Signing.PublicKey]

    func verify<T: Decodable>(_ envelope: SignedEnvelope, as type: T.Type) throws -> T {
        guard let key = publicKeys[envelope.keyID],
              let payload = Data(base64Encoded: envelope.payload),
              let signature = Data(base64Encoded: envelope.signature),
              key.isValidSignature(signature, for: payload)
        else {

        return try JSONDecoder.commercial.decode(T.self, from: payload)
