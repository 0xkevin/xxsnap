# XxSnap 收费开关运营检查表

## 先记住一句话

现在所有版本、所有功能都免费。后台虽然已经有收费规则、十四天试用和手工激活码，但支付还没有上线，绝对不能对外收费。

以后 Pro 也只包含三个功能：滚动截图、OCR、教笔。区域截图、全屏截图、贴图、保存、复制、形状、画笔、箭头线、线型、调色板、字体、快捷键和其他现有功能都属于 Free。

计划中的授权规则是：

- Pro 可完整试用十四天；
- 一份授权最多三台设备，只允许一个人使用；
- 购买后永久使用授权范围内的 Pro，并包含十二个月更新；
- 正式价 68 元，首发价 48 元，续十二个月更新 34 元；
- 实际价格、试用天数和设备数以客户端验签通过的后台规则为准，不能靠口头通知改。

## 每次操作都要遵守

1. 只进管理后台的“收费与授权”页面：`https://admin.xxsofts.com/commercial`。
2. 任何改规则、退款、撤销或解绑操作，都先截图记录工单号和操作原因，再由第二个人核对。
3. 不在聊天、工单、邮件、截图或 Shell 命令里粘贴私钥、设备哈希 secret、激活码、邮箱、完整签名凭证。
4. 操作后用下面的只读命令看公开规则。这个命令不需要登录，也不包含 secret：

   ```bash
   curl --fail --silent --show-error \
     --connect-timeout 5 --max-time 15 \
     -H 'Cache-Control: no-cache' \
     https://download.xxsofts.com/api/v1/commercial/policy
   ```

5. 预期返回只有 `keyId`、`payload`、`signature` 三个字段。不要自己把 Base64 payload 当成可信规则；必须由客户端或部署门禁验签成功后才能相信。

## 续签“全部免费”规则

什么时候做：规则到期前七天开始，不要等到最后一天。

怎么做：

1. 打开“收费与授权”页面。
2. 选择“当前所有功能免费”。
3. 不勾“计费已就绪”。
4. 滚动截图、OCR、教笔三个收费选项全部不勾。
5. 生效时间填当前时间附近，到期时间建议填三十天后，不能超过后台允许的三十天。
6. 点击发布，按弹窗要求输入“保持全部免费”。
7. 执行上面的只读 `curl`，再用已发布的 Debug 客户端点一次三个功能。

预期结果：后台显示“当前所有功能免费”；客户端不显示 `PRO`、购买入口或试用倒计时；滚动截图、OCR、教笔都能直接使用。

失败怎么办：立即停止继续操作。不要改数据库，不要重启用户电脑。若旧规则还有效，保留旧规则并查后台错误；若错误规则已经发布，执行“一键紧急全免费”。

## 确认三个功能现在免费

1. 后台首页状态必须是“当前所有功能免费”和“Billing readiness 未就绪”。
2. 用当前正式客户端、上一正式客户端各检查一次滚动截图、OCR、教笔。
3. 查看客户端诊断事件时，只接受 `policy_mode=all_free` 这一类不含身份的信息。

预期结果：三个功能都能用，入口没有 `PRO`，设置页没有“授权与购买”。

失败怎么办：先点“紧急恢复全部免费”，再查规则是否过期、key ID 是否在客户端公钥表里、客户端是否报告稳定错误码。不要让用户反复卸载重装。

## 生成内部测试激活码

第一阶段的激活码只用于内部验收，不能出售。

1. 进入“收费与授权”页面下方的“授权管理”。
2. 点击创建授权，填写公司的测试邮箱、测试购买时间和十二个月后的更新截止时间。
3. 创建后激活码只显示一次。把它放入公司批准的密码管理器，并勾选“我已安全保存激活码”后再关闭弹窗。
4. 在隔离的测试后台或测试设备上输入邮箱和激活码，不能为了测试把生产规则改成收费。

预期结果：测试设备显示授权有效，设备数从 0 变成 1，最多可增加到 3。

失败怎么办：不要从数据库找明文码，数据库本来就不保存明文。作废这次测试授权并重新生成；不要把激活码发到群聊或工单。

## 为什么支付没做好不能勾 `billingReady`

`billingReady` 的意思不是“页面看起来差不多了”，而是购买、收款、发码、找回、设备管理和退款都能完整跑通。现在这些第二阶段功能还没完成。

下面四项必须全部上线并验收，才能讨论收费：

1. 官网中文和英文 Pro 购买页；
2. 微信支付和支付宝支付；
3. 防重复的支付回调、订单和退款；
4. 激活码邮件发送、找回和网页设备管理。

在此之前，服务器配置 `XXSNAP_COMMERCIAL_BILLING_CAPABILITY_ENABLED` 必须精确为小写 `false`。即使管理员误勾 `billingReady`，部署门禁也必须失败。

## 将来二次确认开始收费

这段现在不能执行，只是给第二阶段预留的清单。

1. 四项支付条件分别有验收记录，并完成退款、重复回调、邮件失败和设备满额演练。
2. 新旧客户端都能识别当前签名 key，免费工具回归通过。
3. 两名负责人共同核对价格、十四天试用、三设备、十二个月更新和三个 Pro 功能。
4. 按单独的第二阶段部署计划把服务器 capability 改为 `true`，先走候选健康和签名门禁。
5. 后台选择“已开始收费”，勾 `billingReady`，只勾滚动截图、OCR、教笔，并按弹窗输入“开始收费”。
6. 小范围观察后再扩大，不允许绕过部署门禁直接改数据库。

预期结果：新设备首次收到付费规则后获得十四天试用；试用结束只限制三个 Pro 功能；Free 功能始终可用。

失败怎么办：立刻执行“一键紧急全免费”，恢复服务器 capability 为 `false`，按第二阶段回滚计划处理。不要删授权数据。

## 一键紧急恢复全部免费

什么时候用：购买、激活、签名、授权服务器或规则配置出现可能影响用户的故障时。

1. 打开“收费与授权”页面的“安全兜底”。
2. 点击“紧急恢复全部免费”。
3. 按弹窗输入“紧急恢复全部免费”。
4. 用公开规则只读命令检查，再让测试客户端主动刷新。

预期结果：新规则立刻是 `all_free`、`billingReady=false`，三个收费标志都是 `false`；客户端刷新后所有功能恢复，购买页隐藏。

失败怎么办：不要反复点击。保留现有服务，联系值班开发检查后台、数据库和签名配置；部署新版本时门禁仍会阻止不安全规则切流。

## 识别规则签名失败

常见现象：客户端继续使用上次验签成功的规则，或在免费规则过期加十四天离线宽限后只保留 Free；诊断只记录 `stable_error_code`、`policy_mode`、`policy_id`、`request_result` 等脱敏字段。

检查顺序：

1. 公开接口是否返回 HTTP 200；
2. 是否只有 `keyId`、`payload`、`signature`；
3. key ID 是否在该客户端内置公钥表；
4. 部署门禁是否报告 JSON、Base64、签名、时间或免费状态错误；
5. 服务器时间是否准确，规则是否已生效且未过期。

不要用网页 Base64 解码工具，不要把完整信封粘贴到第三方网站。验签失败时不能手工告诉用户“忽略错误”。先紧急全免费，再发布使用可信 key 的新规则。

## 新旧公钥轮换

公钥轮换必须有重叠期，顺序不能反：

1. 生成新 key pair。私钥只进服务器秘密配置；工单只记新 key ID。
2. 先发布同时内置旧公钥和新公钥的客户端。
3. 等到仍在使用的客户端绝大多数都升级后，把服务器部署门禁的 `XXSNAP_COMMERCIAL_TRUSTED_PUBLIC_KEYS` 配成同时包含新旧 key 的 JSON 表。
4. 候选部署验证通过后，才把服务端活动签名 key ID 和私钥切到新 key。
5. 保持旧公钥一段明确的兼容期。确认不再有受支持客户端依赖后，才在后续客户端和部署配置中移除旧 key。

预期结果：切换前后的新旧客户端都能验签，不出现集中降级。

失败怎么办：在旧私钥没有泄露的前提下，立即切回旧活动 key，并发布新的全免费规则。若私钥疑似泄露，不能再用旧私钥，直接走安全事件流程和紧急客户端更新。

## 误退款、误解绑和服务器故障

误退款：退款状态会让联网校验后的授权失效。不要直接改数据库恢复。确认没有真实退款后，由负责人创建新的替代授权，记录原授权 ID 和原因，把新激活码通过批准的安全渠道交付。

误解绑：已停用的同一设备不能直接拿原码重新占回原记录。确认操作错误后，用剩余设备或替代授权恢复；需要改变这一规则时必须走代码修改和审计，不能改表。

服务器故障：已购买并成功验签、且当前版本在更新范围内的用户按永久授权失败开放，不应因为临时断网降级。试用和全部免费规则最多使用已验签状态加十四天离线宽限；宽限结束后只保留 Free。故障期间先恢复服务或紧急全免费，不要要求用户清钥匙串、卸载重装或修改系统时间。

## 哪些日志绝对不能发给客服

下面内容无论是文字、截图还是压缩包，都不能直接发送：

- 激活码、恢复码、会话 token、Authorization/Bearer 内容；
- 签名私钥、设备哈希 secret、任何环境变量 secret；
- 完整签名 payload、signature 或授权 credential；
- 邮箱、完整设备 hash、license ID、credential ID；
- 截图/OCR 原文、用户输入文字、剪贴板内容、图片、文件名和完整路径；
- 未经过 XxSnap 内置导出器脱敏的原始日志和候选服务日志。

可以发送的是内置“导出诊断”生成并再次人工检查过的压缩包，以及这些白名单字段：`policy_mode`、`policy_id`、`policy_expired`、`access_kind`、`commercial_feature`、`request_result`、`stable_error_code`。即使使用内置导出，也要先打开检查一遍再发。
